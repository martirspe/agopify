## Module

`apps/api/src/commerce-integrations/` — **not** the plan feature module `integrations/`.

| Piece | Path |
| --- | --- |
| Adapter contract | `commerce-platform.types.ts` |
| Registry | `platform-registry.service.ts` |
| Magento / Woo | `adapters/magento.adapter.ts`, `adapters/woocommerce.adapter.ts` |
| Plataformas mapeadas (stubs) | `adapters/mapped.adapters.ts` (`connectable: false`) |
| Credentials | `commerce-credentials.service.ts` + `INTEGRATION_CREDENTIALS_KEY` |
| SSRF guard | `safe-store-url.ts` |
| Catalog upsert | `catalog-sync-writer.service.ts` → existing `Product` |
| Sync / BullMQ | `commerce-sync.service.ts` (inline fallback without Redis) |
| HTTP | `/api/v1/commerce-integrations…`, webhooks `/api/v1/webhooks/commerce/:platform/:id` |
| Console | `/app/commerce-integrations` (overview / sync / connect / upcoming) |
| Settings | `PATCH /commerce-integrations/:id/settings` |
| Retry | `POST /commerce-integrations/:id/sync/:executionId/retry` |

## Adding a platform

1. Implement `CommercePlatformAdapter` (declare real capabilities only).
2. Register in `PlatformRegistryService` + Nest module providers.
3. Add `CommercePlatform` enum value + migration if new.
4. Set `connectable: true` only when validate/fetch/normalize work end-to-end.
5. Wire console card; no simulated sync stats.

## Env

```
INTEGRATION_CREDENTIALS_KEY=<32-byte hex or base64>
```

Generated by `scripts/setup-local.mjs` and `scripts/deploy.sh` when empty. Never rotate after connections exist without a re-seal plan.
